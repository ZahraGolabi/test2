## ۲) انیمیشن‌ها

| انیمیشن                    |            Property           |                 مرحلهٔ اجرا |
| :------------------------- | :---------------------------: | --------------------------: |
| بنر Hero                   |           `opacity`           |               فقط Composite |
| بالا آمدن کارت هنگام Hover | `transform: translateY(-4px)` |               فقط Composite |
| سایهٔ کارت                 |  `opacity` روی `::after` ثابت |               فقط Composite |
| منوی موبایل                |    `opacity` و `transform`    |               فقط Composite |
| حرکت کاروسل                |       اسکرول بومی مرورگر      | روی Compositor، بدون Layout |
| Hover دکمه‌ها              |  `background-color` و `color` |           Paint (عنصر کوچک) |

از `width`، `height`، `top` و `margin` استفاده نشده، پس Layout دوباره اجرا نمی‌شود و عناصر دیگر جابه‌جا نمی‌شود. سایه را مستقیم انیمیت نکردم چون `box-shadow` باعث Paint می‌شود. برای کاروسل هم اسکرول بومی از هر انیمیشن دستی سبک‌تر است. در `prefers-reduced-motion` انیمیشن‌ها خاموش می‌شوند.

در بنر، دکمه‌ها با انیمیشن `visibility` ظاهر و پنهان می‌شوند. این Layout نمی‌سازد ولی ممکن است Paint کوچکی داشته باشد.

## ۳) منوی موبایل

منوی موبایل با `<input type="checkbox">` و `<label>` باز و بسته می‌شود.

حالت بسته:

```css
opacity: 0;
visibility: hidden;
transform: translateY(-8px);
```

`visibility: hidden` باعث می‌شود منوی مخفی هم از دید کاربر و هم از دسترسی کیبورد و صفحه‌خوان خارج شود؛ یعنی کاربر نمی‌تواند با Tab روی لینک‌های مخفی برود.

اگر فقط `opacity: 0` استفاده می‌کردیم، منو دیده نمی‌شد، اما لینک‌های آن همچنان با Tab قابل انتخاب بودند.

چک‌باکس با `.sr-only` پنهان شده، نه `display: none`، پس با کیبورد (Tab و Space) قابل استفاده است و حلقهٔ فوکوس روی دکمهٔ منو نشان داده می‌شود.

زیرمنوی دسکتاپ هم با `:hover` و `:focus-within` باز می‌شود تا کیبورد هم به آن برسد.

## ۴) URL Fragment

**هیچ چیز به سرور ارسال نمی‌شود.** قسمت بعد از `#` فقط در مرورگر پردازش می‌شود و در درخواست HTTP نمی‌رود.

مرورگر در همان صفحه به عنصری با `id="dairy"` اسکرول می‌کند. به همین دلیل صفحه دوباره بارگذاری نمی‌شود و ارسال لینک، همان بخش را باز می‌کند.

`scroll-padding-top` (متغیر `--sticky-offset`) مانع پنهان شدن تیتر زیر هدر چسبان می‌شود و `:target` بخش مقصد را هایلایت می‌کند.

## ۵) کاروسل بدون JavaScript

**حرکت:** با `overflow-x: auto` کاروسل قابلیت اسکرول افقی دارد و با `scroll-snap-type: x mandatory`، اسکرول همیشه روی ابتدای یک کارت قرار می‌گیرد. لمس، چرخ ماوس، تاچ‌پد و کیبورد (فلش‌ها، Home و End) هم کار می‌کنند.

**دکمه‌ها:** دکمه‌های حرکت را خود مرورگر با `::scroll-button(inline-start)` و `::scroll-button(inline-end)` می‌سازد. این دکمه‌ها در ابتدا و انتهای کاروسل به‌صورت خودکار غیرفعال می‌شوند و با Anchor Positioning کنار عنوان قرار می‌گیرند.

## ۶) دسترس‌پذیری

* لینک پرش به محتوای اصلی که فقط با Tab دیده می‌شود
* حلقهٔ فوکوس واضح با `:focus-visible`
* فقط یک `h1` و ترتیب درست عنوان‌ها (`h2`، `h3`، `h4`)
* `alt` برای تصاویر معنادار، `aria-label` برای دکمه‌ها و آیکون‌ها
* اندازهٔ هدف لمسی حداقل ۴۴px
* رنگ‌های متن با کنتراست حداقل ۴٫۵ به ۱
* `prefers-reduced-motion`

## ۷) لوگو

* یک `rect` سبز گوشه‌گرد (پس‌زمینهٔ آیکون)
* یک `path` سفید برای بدنهٔ سبد و یک `path` برای دسته‌ها
* چهار `path` نارنجی برای فلش‌های چرخشی (نماد ریفکتور)
* دو `text` برای نام و شعار

بدلیل کم حجم بودن و رنگ‌پذیری آن و اینکه در هر اندازه‌ای شفافیت خود را حفظ می‌کند و یک تصویر برداری است.
